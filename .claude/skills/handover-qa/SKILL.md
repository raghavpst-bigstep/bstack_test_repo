# /handover-qa — QA Summary & Known Issues

Produces deliverable **07**: an honest account of the product's quality at handover — what was tested, the results, and what is known to be broken or limited. Honesty here protects both sides: hidden issues become disputes; disclosed issues become managed expectations.

> **Shared contract** — output location & numbering, secrets → doc 05, actual-state-not-plan, cross-referencing, and completeness rules live in [`handover/references/handover-conventions.md`](../handover/references/handover-conventions.md). Follow it; don't restate it.

## When to use

- The client needs to know the quality/test status of what they're accepting.
- You must hand over a known-issues register and any deferred bugs (cross-references doc 01 open items).

## Inputs to gather

- Test suites and how to run them; latest results and coverage numbers (run them if possible).
- UAT/acceptance test outcomes.
- Any performance, load, security, or accessibility testing done.
- The open bug list from the issue tracker, with severities.
- Browser/device/environment support matrix.

## Process

1. Describe the **test strategy**: what types of testing were done (unit, integration, e2e, manual, UAT) and the philosophy.
2. Report **execution results** — pass/fail counts, coverage, and **run them now** if you can rather than quoting stale numbers.
3. Report **non-functional checks**: performance, security, accessibility — including "not performed" where true.
4. Report **UAT outcome** and link acceptance evidence (doc 01).
5. Compile the **known-issues register**: each issue with severity, impact, workaround, and disposition.
6. Provide the **support matrix** of browsers/devices/OS validated.

## Quality checklist

- Numbers come from an actual run at handover time, not memory — state the date and command.
- Failing tests and open bugs are disclosed, not hidden; severities are honest.
- "Not performed" is stated plainly for any check that wasn't done (e.g. no load testing).
- Each known issue has a disposition consistent with the open items in doc 01.
- Security findings reconcile with any security review results.
